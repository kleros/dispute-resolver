# Deviations ledger

Every place where the new app deliberately behaves differently from the behavioral spec. A difference not recorded here is a regression. Copy wording, layout, colors and component choice are not deviations; state machines, data shown, actions available, links and their targets, and error behavior are.

Each entry: **Today** (what the current app does, with the spec's tag), **New** (what the rewrite does), **Why**, **Test** (how the golden suite or a unit test checks it). D-01 to D-13 are the thirteen quirks Q1 to Q13 of the spec, in the same order.

## Quirks fixed (Q1–Q13)

**D-01 · Redirect targets** (Q1). Today: `/:chainId/` and `/:chainId/disputes` redirect relatively to `/:chainId/:chainId/ongoing`, a 404; chain-less legacy paths (`/ongoing`, `/cases/5`) treat the first segment as a chain and show "Unsupported Network ongoing". New: those paths redirect to `/:chainId/ongoing`; a chain-less path redirects to the same path under the default chain (1) or the wallet's chain when connected. Why: dead links in shared URLs. Test: Playwright route table.

**D-02 · Contribution and RulingFunded scan windows** (Q2). Today: with an anchor block the scan covers only `[anchor, anchor + 10,000]`, so contributions made more than ~33 hours after an appeal are missed; past rounds in execution are anchored at dispute creation; a reload scans a different range and shows different totals. New: scans run from the round's start block to the latest block (chunked where the RPC caps ranges). Why: wrong amounts and wrong "funded" states. Test: golden Gnosis 121 and 132 totals equal the on-chain sums under the account context of 04 §1.

**D-03 · "Appealed" markers** (Q3). Today: never rendered because the component receives an undefined prop. New: an "Appealed" marker appears in the evidence timeline at each `AppealDecision` block. Why: the information is fetched and intended. Test: mainnet 328, Gnosis 121.

**D-04 · Variable-type appeal cards** (Q4). Today: uint, int, string, datetime and hash questions also get the "Yes"/"No" fallback cards; the current-ruling variable card uses the loser amount. New: variable-type questions show only the variable cards (contributed values, current ruling, free input); the current-ruling card uses the winner amount and deadline. Why: nonsensical cards and wrong required amount. Test: mainnet 1658 history; Sepolia S2, S3.

**D-05 · Script result channel** (Q5). Today: one global `window.onmessage` handler, overwritten per run; concurrent runs (the Ongoing page) cross-resolve and cache the wrong result forever. New: per-run `MessageChannel` port (ADR 0004). Why: wrong titles on the Ongoing page; weakness B8 (the spoofing weakness B1 shares the fix). Test: unit test with two concurrent runs.

**D-06 · Wallet connection at load** (Q6). Today: `eth_requestAccounts` fires on page load whenever the wallet exposes no connected account; rejecting it leaves the app on "Please enable a web3 provider." until reload; injected wallets only; the active address is read from a legacy MetaMask property. New: the app loads read-only and never prompts; the user connects on demand through AppKit (any browser wallet via EIP-6963, WalletConnect, Coinbase); rejecting a prompt returns to read-only. The Safe in-app frame is not supported because the app forbids being framed (checklist C1). Why: the auto-prompt breaks the session and locks out non-injected wallets. Test: Playwright read-only load; unit test on the wagmi config (C8).

**D-07 · Silent transaction failures** (Q7). Today: create-dispute, evidence-submission, fund-appeal and withdraw errors are swallowed or only logged; the evidence modal closes on failure; the evidence reload fires immediately. New: every write path reports success, pending and failure to the user; a failed submission keeps the modal open with the error; the user-rejected-signature case is not shown as an error; after a confirmed evidence submission the list refetches once the transaction is mined instead of reloading the page. Why: users cannot tell whether an action happened. Test: Playwright with a rejected signature on Sepolia S1.

**D-08 · Create form behavior** (Q8). Today: the form resets to its initial state when courts finish loading or the network changes; a single party row with add/remove handlers that are never rendered; changing the number of options does not trim titles already typed; returning from the summary page recomputes the cost for court 0 and shows "Please select a court" for a restored court 0; the dropzone never shows its uploading or file-name text because the form does not pass those props. New: input is preserved while courts load; multiple parties with add and remove controls; option titles are trimmed to the chosen count; returning from the summary keeps the chosen court and its cost; the dropzone shows upload progress and the selected file name; party addresses are validated with `isAddress` and duplicates rejected, and names stay paired with their addresses. Why: data loss and mislabeled aliases (weakness B20). Test: component tests; Sepolia S1.

**D-09 · Case page without an ID** (Q9). Today: `/:chainId/cases` loads dispute 0 and renders a stray "0". New: shows the search box with no dispute loaded. Why: accidental dispute 0. Test: Playwright.

**D-10 · Currency labels** (Q10). Today: withdraw and Escrow appeal buttons say "ETH" on every chain; the create form uses the chain's currency. New: every amount uses the chain's currency symbol. Why: wrong on Gnosis. Test: Gnosis 121 withdraw panel.

**D-11 · Dead code and dead fetches** (Q11). Today: seven undefined props passed to the case page, an unused appeal-cost callback that targets the wrong contract, `ruling` and `getDispute` results fetched twice and never rendered, the "Non-Standard Contract" banner whose producer was removed, two unused ABIs, the duplicated `getDispute`, the dead withdraw retry branch, the unused dispute-struct and appeal-period callbacks, and the fallbacks made unreachable by sanitization (the list is not exhaustive). New: none of it exists. Why: noise and wasted RPC calls. Test: none needed beyond the absence.

**D-12 · Escrow V1 detection** (Q12). Today: case-sensitive `.includes` against a list in which `0x0d67440946949fe293b45c52efd8a9b3d51e2522` is lowercase, so that escrow never matches and falls through to the IDisputeResolver path (its disputes show the fees-unavailable warning instead of the Escrow appeal). New: family detected by selector probe (ADR 0003), addresses normalized. Why: wrong appeal UI. Test: mainnet 168 and 92 render the Escrow appeal panel (expected difference from production).

**D-13 · Meta-evidence cache** (Q13). Today: cached in localStorage under `${chain}${disputeId}` with no separator, no version and no expiry; read without validation. New: TanStack Query persisted cache, versioned, entries validated by schema on read, same for the subcourt cache. Why: stale entries mask fixes; weakness B15. Test: unit test that a version bump invalidates.

## Bugs found during research

**D-14 · Error alert crash.** Today: the crowdfunding card renders an alert of type `danger`, which the alert component has no icon for, so React throws exactly when an error should be shown and the whole page blanks. New: alert types are a closed set and the error path renders. Test: component test.

**D-15 · Zero decimals ignored.** Today: uint answers are encoded with `precision || 18`, so a question with `decimals: 0` is encoded with 18 decimals while display honors 0. New: precision 0 is respected. Test: encoder unit test with a `decimals: 0` fixture; the create form writes no `precision`, so Sepolia S2 cannot exercise this.

**D-16 · Negative integers.** Today: int answers below zero are encoded without the `+1` offset or two's complement. New: int encoding follows reality-eth-lib's rule for the full range. Test: unit test.

**D-17 · Datetime precision.** Today: datetime appeals are truncated to UTC midnight although the picker shows a time. New: the chosen timestamp is encoded. Test: Sepolia S3.

**D-18 · Unknown chain IDs.** Today: `getReadOnlyRpcUrl` throws for a chain not in the map, which crashes the case page when a meta-evidence names such a chain. New: unknown chain IDs degrade to "no RPC configured for chain N" within the affected section. Test: component test with `arbitrableChainID: 10`.

**D-19 · Courts never finish loading.** Today: one failed policy fetch rejects the whole subcourt load, leaving the court dropdown on "Loading..." and the case page without details forever. New: each court's policy is fetched independently; a failed one shows its ID with "name unavailable". Test: unit test with one failing fetch.

**D-20 · Atlas sessions per tab.** Today: the sign-in token lives in localStorage and survives across tabs and browser restarts until it expires. New: the shared `@kleros/kleros-app` provider keeps it in per-tab session storage; a reload of the same tab keeps the session, a new tab or restart asks for a new signature; a token without `exp` is treated as expired. On account switch the library keeps the token but marks the session unverified (today the token is cleared); for the user the effect is the same, the upload controls require a new sign-in. The library issues one unauthenticated `roles(product)` request at load to learn the per-role upload limits (today: no such request). Why: shared library, the v2 norm, smaller exposure (ADR 0002). Test: Playwright sign in, reload, still signed in; switch account, upload controls gated again.

**D-21 · Missing Atlas configuration.** Today: an unset `REACT_APP_ATLAS_URI` throws at module load and the whole app fails to boot. New: uploads are shown as unavailable; everything else works. Test: unit test.

## Deliberate changes from the design

**D-22 · Evidence URIs must be content-addressed.** Today: archon trusts any `/ipfs/` URI and multihash-checks https ones; failing items are hidden silently. New: an evidence entry is shown only if its URI is content-addressed and its JSON matches the schema; the number of hidden entries is shown ("2 evidence items hidden: not content-addressed"). Why: the Court rule (kleros/court#594); weakness B7. Test: component test; golden cases with hidden counts noted.

**D-23 · Chains dropped.** Today: 17 configured chains plus arbitrator rows for chains 3, 4, 42 and 77 that have no map entry, explorer strings for Ropsten and Kovan, a Görli row without an RPC variable, a Mumbai row pointing at the Görli arbitrator, a typo in the Base Sepolia query-from-block key. New: Görli (5), Mumbai (80001) and the dead rows are gone; the other 15 chains stay as data; every Reality home chain referenced by the registry has an RPC (invariant test). Why: dead configuration. Test: config invariant tests.

**D-24 · Content-addressing check hardened.** Today: any path after a valid CID passes, including dot segments that resolve to `/ipns/`. New: URL normalized first; the first path segment must be the CID. Why: weakness B2. Test: unit tests with the bypass URLs.

**D-25 · Dispute 1621 override removed.** Today: mainnet dispute 1621 fetches script `Qmf1k727…` instead of its meta-evidence's `QmdpXX…`; the override CID sits in the allowlist. New: the original script runs; the runner's RPC redirect matches provider hosts by pattern (any `https://<net>.infura.io/v3/<key>` to the configured RPC for that chain) instead of one exact URL, which repairs this and the Linguo scripts. Why: the two scripts are identical except for a dead API key (ADR 0003). Test: equivalence gate row for 1621.

**D-26 · T2CR display override replaced by a gateway rule.** Today: arbitrable `0xEbcf3bcA…` has its evidence display hardcoded to `/ipfs/QmYs17m…/index.html`. New: any display or attachment URL whose normalized path begins with `/ipfs/<CID>` is served from the configured gateway, so the T2CR meta-evidence's `https://ipfs.kleros.io/ipfs/QmYs17m…/index.html` resolves without naming the contract; the result must still pass the content-addressing check. Meta-evidence URIs themselves keep today's rule (must be content-addressed; absolute URLs rejected). Why: generic rule first (ADR 0003). Test: mainnet 1255; unit test with the dot-segment URL.

**D-27 · Second "Unslashed" address removed.** Today: `0xb9f9B5eee2ad29098b9b3Ea0B401571F5dA4AD81` is in the exceptions list. New: gone; it has no code on any checked chain. Test: registry snapshot.

**D-28 · Self-link rule.** Today: the "Go to arbitrable application" link is hidden when its URL contains the substring `resolve.kleros.io`. New: hidden when the URL's host equals the app's host or a configured canonical host (`resolve.kleros.io`). The default dynamic script and the create flow keep emitting the self-link for parity with existing disputes; the host rule hides it. Why: substring matching; deploy previews have other hosts. Test: unit test.

**D-29 · Script sandbox.** Today: `blob:` iframe from the `iframe` package, `allow-same-origin` for allowlisted arbitrables, parameters embedded in HTML, global message handler, frame never removed. New: dedicated runner page, `allow-scripts` only, explicit UTF-8, parameters by `postMessage`, per-run port, frame removed on settle, header-delivered sandbox and bootstrap guards (ADR 0004; checklist B1, B4, B5, B8, C3, C4). User-visible consequence: Reality renderer scripts run for unregistered proxies now return their ruling options where production returns `{}` because of the charset fallback (04 §5 gate rule). Concurrent runs are capped at four at a time to stay under provider rate limits; today the Ongoing page starts one frame per dispute at once. Why: weaknesses B1, B4, B5, B8. Test: unit tests, C6 gate, C7 charset test.

**D-30 · Unslashed round offset applied uniformly.** Today: the `+1` round offset is applied to `Contribution` scans only before the execution period, and to `RulingFunded` scans always. New: the offset applies in every period to both scans. Why: the contract increments rounds without appeal events in every period; the current inconsistency has no recorded reason. **To verify** on mainnet 1678 (executed, contributions and withdrawals) and 1226 before the registry entry is final; if 1678 shows different totals, the rule is reconsidered and this entry updated. Test: golden 1678 and 1226.

**D-31 · Markdown links and images.** Today: description links open in the same tab without `rel`; images load from any host. New: links open in a new tab with `rel="noopener noreferrer"`; images only from https sources. Why: weakness B14. Test: component test.

**D-32 · Plain `http://` links.** Today: an absolute `http://` attachment or interface URL is linked as is. New: only https URLs are linked; an `http://` value is shown as text. Why: weakness B19. Test: unit test.

**D-33 · Multiple-select appeal cards capped.** Today: 2ⁿ combination cards are rendered for n option titles, which hangs for large n. New: combination cards are rendered when n ≤ 8; above that, a picker lets the user select options and computes the ruling code, with the same fund action. Why: weakness B12. Test: component test with n = 9.

**D-34 · Display allowlist lookup key validated.** Today: the evidence-display flag tier is looked up under `metaEvidence.arbitrableChainID`, an unvalidated value the dispute creator controls, falling back to the arbitrator chain. New: same key, same membership and therefore the same flags for every existing dispute, with the chain ID accepted only when it is an integer naming a configured chain (otherwise the arbitrator chain is used). Why: weakness B6, accepted with this mitigation; re-keying by arbitrator chain was rejected because several entries have no arbitrator chain to move to and it would change flags for cross-chain disputes. Test: unit test.

**D-35 · RPC URLs given to third-party frames.** Today: the configured read RPC, which may include an API key, is passed to evidence displays and scripts. New: a per-chain `REACT_APP_PUBLIC_RPC_<chain>` setting is passed instead, defaulting to the read RPC. Why: weakness B13. Test: unit test on the parameter builder.

**D-36 · Section-level degradation.** Today: no error boundary; several malformed inputs blank the page (unknown chain ID, non-string title, missing `votesLengths`, courts not loaded, missing court for a card), and a failed Dispute-event read shows "Invalid Date" as the creation time; failed reads are replaced by fake fallback structs (`numberOfChoices: "2"`, zero periods). New: each section has an error boundary and renders "unavailable" with the reason; no fake data. Why: the project rule that bad disputes must not crash the app. Test: the bad-dispute golden cases (1665, 1666, 150, 560, Gnosis 115, 140).

**D-37 · Ongoing page loading.** Today: the spinner stays until every dispute's meta-evidence settles, each with a 120-second retry budget, so the list can spin for minutes; a per-dispute failure drops the card. New: cards render as each dispute resolves; a dispute whose meta-evidence fails shows its ID with "title unavailable"; the per-dispute budget is bounded well under a minute. Why: usability of the main list. Test: Playwright timing and the failed-title case.

**D-38 · Meta-evidence fetch budget.** Today: 120 seconds of retries at 5-second intervals, checked only before each attempt, with a 180-second script timeout that exceeds the budget, so one call can last more than three minutes. New: one bounded budget for fetch plus script, with the script timeout inside it; failures are cached briefly rather than retried on every render. Why: coherence; D-37. Test: unit test.

**D-39 · Timeline columns.** Today: Evidence, Voting and Appeal only; the commit period shows as Evidence concluded and Voting upcoming; execution has no column. New: the timeline shows every period the dispute passes through, including Commit for hidden-vote courts and Execution. Why: hidden-vote courts (Gnosis court 19) are misrepresented. Test: Gnosis 1037 while in commit (live tier), any executed case.

**D-40 · Explorer links.** Today: one Etherscan link in the footer, reachable only on mainnet. New: addresses and transactions link to the chain's explorer on every configured chain. Why: usability. Test: component test per chain.

**D-41 · Response headers.** Today: none. New: checklist C1–C3. Test: deploy tests.

**D-42 · Dependencies and stack.** Today: see ADR 0002 context. New: see ADR 0002. Behavior-relevant consequence recorded here: `react-markdown` moves from v4 to a current version with the same escaping guarantee (A11 tests); the date picker is re-chosen with the same accepted input; the dropzone enforces the size limit and MIME types Atlas serves per role before uploading, where today a fixed 20 MB limit applies, any type is accepted, and rejected types fail with a server error.

**D-43 · Period-3 appeal text.** Today: in the appeal period the explanatory paragraph also prints "You don't have any amount to withdraw…" because of how the conditional is written. New: the withdraw text appears only in the execution period. Test: component test on a period-3 fixture.

**D-44 · Evidence modal state.** Today: after a successful submission the modal keeps the uploaded document, so a second submission without choosing a new file silently reuses the previous attachment. New: the modal resets all fields, including the attachment, after a successful submission. Test: component test; Sepolia S1.

**D-45 · Header links on error screens.** Today: on the unsupported-network and 404 screens the header builds its links from an undefined route parameter, producing `/undefined/ongoing` and similar. New: header links always use the resolved chain. Test: Playwright on an unsupported chain.

**D-46 · Contracts with IDisputeResolver IDs but no withdraw functions.** Today: the older resolver proxy `0x135c5735…` (70 mainnet disputes) answers `externalIDtoLocalID`, so it is treated as compatible; its withdraw reads throw and the panel shows zero, and an appeal funding attempt calls a `fundAppeal` signature it does not have. New: family `idr-legacy` (06 §1): evidence as today, appeal funding through the `fundAppeal` selector the contract actually carries, and the execution-period panel says withdrawals are not supported through the resolver for this contract instead of showing zero. Why: the probe order would otherwise downgrade a working arbitrable to view-only. Test: mainnet 505 and 328; bytecode fixture.

**D-47 · Appeal panel for families that cannot fund.** Today: the appeal panel is not gated by compatibility; in the appeal period a view-only or governor dispute shows crowdfunding cards when its multipliers are readable (or the fees-unavailable notice), and a fund attempt fails and crashes on the error path (D-14); in execution it shows the withdraw body with nothing withdrawable. New: per-family, per-period panel as in 06 §1: families without `fundAppeal` show a note that appeals are handled in the arbitrable application and no cards, and no panel in execution. Why: cards that cannot fund. Test: golden 1674, 1646, 1255, 1659, 1621, 1672, 535, Gnosis 1022 (expected difference); live-tier PoH v2 in appeal.

**D-48 · Wallet chain must match the page chain.** Today: a transaction is signed on whatever chain the wallet is on; when the URL chain differs and the switch request is declined, reads show one chain while writes go to another. New: every write first compares the wallet's chain to the page chain and refuses with a message that offers the switch again. Why: weakness B3. Test: unit test of the guard; Playwright with the wallet on another chain.

**D-49 · IDisputeResolver v1 contracts other than Unslashed.** Today: `0x4b89e798…` (mainnet, disputes 912 and 913) and `0x1128ed55…` (Gnosis, dispute 0) are not in the exceptions list, so withdraw is attempted with the v2 signature and reverts silently. New: the version probe selects the v1 signatures for them. Why: the probe replaces the address list (ADR 0003). Test: bytecode fixtures; golden Gnosis 0 withdraw under the account context.

**D-50 · Families detected beyond today's lists.** Today: Escrow V1 and URI-evidence governor behavior applies only to the listed addresses. New: any contract carrying the family's selectors gets the family's write paths (for instance a Sepolia escrow deployment or a new governor). Why: generic rule first. Test: bytecode fixtures for the known deployments; a fixture for an unlisted escrow.

**D-51 · Withdrawals across several rulings.** Today: the total shown is the first ruling with a non-zero withdrawable amount, and the withdraw action covers that ruling only; a contributor to several rulings must reload between withdrawals. New: the panel shows the sum across all rulings the account contributed to and the action withdraws them in sequence, one transaction per ruling, each confirmed by the wallet. Why: the per-ruling behavior is a limitation, not a rule. Test: Sepolia S4 with contributions on both sides.

**D-52 · Atlas sign-in trigger.** Today: an explicit "Sign in" control appears where an upload is possible and the upload controls are disabled until signed in. New: the upload action itself triggers sign-in when needed and continues with the upload once signed (one click); no signature is ever requested before the user's first upload action. Why: shared library flow (ADR 0002). Test: component test; Playwright on Sepolia S1.

**D-53 · Search for a nonexistent dispute.** Today: the previous dispute's arbitrable is not cleared when the search ID changes, so searching a nonexistent ID while a valid dispute is shown displays "Failed to load meta-evidence" instead of the not-found state. New: every search clears the previous dispute entirely and shows the not-found state. Test: Playwright.

**D-54 · Contribution input follows the suggested amount.** Today: the input is initialized once and does not follow later changes of the remaining amount, for instance after a reload. New: the input tracks the remaining amount until the user edits it. Test: component test.

**D-55 · Page chain and wallet chain.** Today: a wallet chain change moves the whole app to the new chain, rewrites the URL and fully reloads the case page; a URL chain that differs from the wallet's triggers a switch request at load. New: the URL is the page chain; a wallet chain change never navigates; the header's chain switcher changes the URL and asks the wallet to switch; writes check the match (D-48). Why: the URL is the shareable identity of a dispute; D-06. Test: Playwright with a wallet chain change while on a case page.

**D-56 · Chain without an RPC variable.** Today: reads fall back to the wallet's provider and then to a public default provider. New: the chain is treated as "no RPC configured": its sections degrade with that message, and nothing reads through the wallet. Why: the read/write split (A13) has no exceptions. Test: unit test.
