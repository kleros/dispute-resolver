# Golden-case gate outputs

Generated by `scripts/golden-gate` (docs/parity/04-golden-cases.md §1, §3 and §5; checklist C6). Everything in this
directory except this README is ignored by git; the files are regenerated on demand and record the block numbers they
were read at. Values from `.env` (RPC URLs and their keys, the meta-evidence API) never appear in them: every output is
redacted before it is written. In `gate-log.*` each run's RPC parameters, and every URL in a failure's detail or a logged
console line (a request URL can carry a third party's key), are recorded as the URL's host and a short SHA-256
fingerprint of the whole URL.

| Command | Writes | What it is |
|---|---|---|
| `yarn golden-gate live` | `live.json` | 04 §3: per chain (1, 100, 11155111, 10200) and per period 0 to 3, the newest open dispute in the Ongoing page's look-back window, preferring one with a `Contribution` event in the appeal period; with the block it was taken at. |
| `yarn golden-gate accounts` | `accounts.json` | 04 §1: for every stable-tier case (`scripts/golden-gate/data/stable-tier.json`, transcribed from 04 §2) and every live-tier case of `live.json`, the first contributor of the dispute's `Contribution` events, or no account and why; with the block of each chain. Run `live` first. |
| `yarn golden-gate enumerate` | `script-references.json` | C6: every dispute of every arbitrator chain whose meta-evidence runs an allowlisted dynamic script in the new app, found through the meta-evidence API (`REACT_APP_METAEVIDENCE_URL`; Chiado through its chain events), and why every other dispute runs none. |
| `yarn golden-gate gate` | `gate-log.json`, `gate-log.md` | C6 / 04 §5: each referencing dispute's script run in a replica of today's runner and in the app's own runner host against the built app (`vite preview`), compared under the 04 §5 rule. The Markdown log is attached to the cutover pull request. |
| `yarn golden-gate all` | all of the above | `live`, `accounts`, then `gate`. |

`cache/ipfs/` holds IPFS files already fetched (content-addressed, so never stale). `yarn golden-gate --help` lists the
options; a run restricted with `--chains`, `--disputes`, `--cids` or `--max-per-cid` is marked partial and is not valid
for the cutover. `--disputes 1:1454,11155111:2` gates those disputes alone, reading only their meta-evidence. Only an
enumeration of every dispute of every chain replaces `script-references.json`, which `--reuse-enumeration` reads. The
exit code is 0 only when the step passed.
